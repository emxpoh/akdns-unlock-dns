## 它做的事只有一件：改 DNS 解析结果

AKDNS 是 DNS 层的解锁与分流服务。工作流程三步：

1. 你的机器把 DNS 请求发给 AKDNS；
2. AKDNS 返回对应区域的解锁节点 IP；
3. 请求从能解锁该服务的地区出口出去。

没在控制台勾选的域名走标准解析，直连，不经过解锁节点。所以官方敢写“不需要 VPN、不需要代理软件、不建立加密隧道、不影响机器上其它业务”，延迟开销也只在被接管的那些域名上。目前覆盖 60 多个服务，地区有香港、日本、美国、新加坡、韩国、台湾、德国、英国八个。

### 和自建 dnsmasq + sniproxy 比，省掉的是哪一步

以前要干这事，标准做法是拿一台能解锁的 VPS，用 dnsmasq 把目标域名全部 `address=/xxx.com/127.0.0.1` 指到本机，再用 sniproxy 监听 80 和 443，按 SNI 或 Host 反代回源站。这个方案能跑，代价是你得维护一份上百条的域名清单，而且 dnsmasq 里写一遍，sniproxy 的 `table` 里还要用正则再写一遍。光是 Akamai 相关的域名就十几个，Netflix 六个，再加 Hulu、HBO、BBC、ABEMA、巴哈姆特，改一次要动两个文件。前置条件还包括开 53 端口、有一台能看奈飞的机器，写教程的人自己都注明“不保证以后的可用性和变更”。

## 这条命令对你的机器做了什么


wget -qO- https://raw.githubusercontent.com/akile-network/aktools/refs/heads/main/akdns.sh | bash


官方发布帖自己把话说在前面：菜单里的“设为系统 DNS”这一项会接管整个系统 DNS，而不只是在配置文件里追加一行 nameserver。具体动作是：

- 停用当前管理 DNS 的组件，systemd-resolved、NetworkManager 的 DNS 管理、resolvconf、netplan 都在处理范围内；
- 直接写入静态 `/etc/resolv.conf`，指向测速选出的最优节点；
- 对 `/etc/resolv.conf` 执行 `chattr +i` 锁定，让 dhclient、cloud-init 在续租或重启时改不动它。

脚本界面里对应的提示是“将统一接管系统 DNS，确保解析直达 AKDNS”，接管方式一栏写着“停用上述管理器 → 直接写入 /etc/resolv.conf”，防覆盖一栏是“锁定 /etc/resolv.conf (chattr +i)”。

这里有一个对生产机很关键的选项：应用分临时和永久两种模式。临时模式在摘要里标“（重启后失效）”，也就是说你只想跑一次测试、不想留下持久改动，选它就行。永久模式才会把上面那套接管动作固定下来。

## UDP 53 被封或被污染，脚本会自己切 TCP

这是 AKDNS 后来补的一项能力。官方的说法是：即使 UDP 53 被封或遭污染，解锁依然稳定，安装脚本会自动检测并切到 TCP，不需要额外配置。

脚本里的实现是，UDP 53 测速全部超时后自动改测 TCP，TCP 可用就写入 `options use-vc` 强制走 TCP，应用摘要里会显示“强制 TCP (options use-vc) —— UDP 已全部超时”。手动输入 DNS 地址时，脚本也会问你要不要强制走 TCP。

两个限制值得先知道：

- Alpine 或 musl 环境会看到提示“musl libc 可能不支持 options use-vc，强制 TCP 或不生效”；
- UDP 和 TCP 都测速超时，脚本会中止，不写任何配置。这是对的，宁可不动也别写一个不通的 DNS 进去。

## “测出来没解锁”，先别急着说服务坏了

脚本里的“流媒体解锁检测”下载的是第三方开源脚本 `1-stream/RegionRestrictionCheck`，界面会明写：检测脚本与结果非 AKDNS 官方。脚本还会往第三方检测里注入 AKDNS 的上下文信息，注入失败就中止执行，避免跑一个没有标注来源的检测。

这条对判断故障很重要。检测结果是第三方脚本给出的地区可用性判断，不等于 AKDNS 的节点状态。如果测出来某项没解锁，脚本自己的引导是：回控制台为本机 IP 勾选要解锁的服务与节点，然后重新跑一次“流媒体解锁检测”复测。规则是按 IP 生效的，你没勾，域名就走标准解析，自然解锁不了。

## 装完不解锁，按这个顺序排查

**第一步看节点通不通。** 公测期有用户在论坛反馈过部分节点连不上，贴出的多个节点 IP 全部返回 timeout 或 unreachable。这类问题会随节点调整变化，但你遇到“完全没反应”时，先确认是不是节点侧的问题，别急着改自己机器。

**第二步看控制台有没有勾服务。** 上面说过，规则按 IP 独立配置，新增 IP 之后要在控制台为它勾选具体服务和节点。

**第三步看测速结果。** 如果脚本报“UDP 与 TCP 测速均超时，未能选出可用 DNS”，它是不会写配置的。换一台机器或换一个网络环境再试，比在原地折腾 DNS 配置文件有效。

## 哪些机器别装

- **正在跑生产业务的机器。** 脚本会停用你现有的 DNS 管理器并锁文件。虽然备份还原路径完整，但生产环境不该为了一次解锁去动系统解析链路。用备用机或单独开一台。
- **Alpine / musl 的机器。** 强制 TCP 可能不生效，你恰好又碰上 UDP 53 被封，这条路就断了。
- **需要全流量代理的场景。** AKDNS 只改 DNS 解析结果，不做隧道也不代理全部流量。你要的是整机出口 IP 变化，它给不了。
- **想解锁清单外服务的人。** 60 多个服务覆盖主流平台，但不在列表里的域名不会被接管。可以到官方反馈渠道提需求，但别指望立刻生效。
- **路由器 / 软路由 / 家庭网关。** 反过来，这类设备反而适合：任何支持自定义 DNS 的设备都能连 AKDNS，装在 OpenWRT 或软路由上可以让局域网设备共享解锁能力，比逐台改系统 DNS 省事。
